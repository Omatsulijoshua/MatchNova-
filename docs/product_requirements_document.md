# Product Requirements Document (PRD) - MatchNova

## 1. Executive Summary
MatchNova is a production-ready, AI-powered dating platform designed to foster meaningful, high-compatibility connections. By leveraging advanced machine learning models, vector-embedded profile data, and real-time interaction mechanisms, MatchNova aims to disrupt the digital dating market (competing directly with Tinder, Bumble, Hinge, and others). The platform ensures user safety, data privacy, and a seamless cross-platform experience (Next.js web and Flutter mobile applications).

---

## 2. Project Objectives
- **High Compatibility Matching**: Shift away from superficial swiping by using multi-dimensional AI profile vector embeddings.
- **Safety First**: Incorporate real-time AI-based image/video moderation and automated fraud/catfish detection.
- **Cross-Platform Parity**: Deliver feature-rich, high-performance web (React/Next.js) and mobile (Flutter iOS & Android) experiences.
- **Enterprise-Grade Infrastructure**: Build a highly available, horizontally scalable microservice architecture with comprehensive observability, security, and failover capability.

---

## 3. Scope & Technology Stack

### 3.1 Frontend & Mobile
* **Dating Web Application**: Next.js, React, TypeScript, Tailwind CSS, Shadcn UI.
* **Mobile App (Android/iOS)**: Flutter, Riverpod (state management), GoRouter (navigation).
* **Dashboards (Admin/Moderator/Support)**: Next.js, React, Shadcn UI.

### 3.2 Backend Services (Microservices)
* **Main API Gateway**: NestJS, TypeScript, Prisma ORM.
* **Auth Service**: JWT, Refresh Tokens, OAuth (Google, Apple, Facebook), Phone OTP.
* **AI Service**: Python, FastStream, PyTorch, OpenAI API, Qdrant/Milvus Vector DB.
* **Notification Service**: Node.js, BullMQ, Firebase Cloud Messaging (FCM), Apple Push Notification Service (APNs).
* **Payment Service**: NestJS, Stripe, Paystack, Flutterwave.
* **Media Service**: Cloudflare Workers, AWS S3/Cloudflare R2, Sharp (image processing).

### 3.3 Database & Caching
* **Primary Database**: PostgreSQL (Multi-AZ, Read Replicas).
* **Caching & Queue Management**: Redis (Cluster Mode), BullMQ.
* **Vector Database**: Qdrant or Milvus for high-dimensional matching.

### 3.4 Infrastructure & Operations
* **Containerization & Orchestration**: Docker, Kubernetes (EKS/GKE).
* **Infrastructure as Code (IaC)**: Terraform.
* **CI/CD**: GitHub Actions.
* **CDN & Edge Security**: Cloudflare (WAF, Rate Limiting, DDoS protection).
* **Monitoring & Observability**: Prometheus, Grafana, Sentry, OpenTelemetry.
* **Product Analytics**: PostHog, Mixpanel.

## 4. Functional Requirements

### 4.1 Authentication & Onboarding
* **Multi-Factor Auth**: Secure login via Phone OTP (Twilio) or Email.
* **Social Login**: OAuth 2.0 integration for Google, Apple, and Facebook.
* **Profile Setup Wizard**: Mandatory fields: Date of birth (age verification), gender, sexual orientation, location (GPS), 3+ photos, and bio.
* **AI Onboarding Assistant**: Opt-in chat assistant that helps users construct their profile questionnaire and drafts their bio using LLMs.

### 4.2 AI-Powered Profile Matching
* **Vector Matching Engine**: Profiles are vectorized based on interests, personality traits, and behavioral patterns. Distance metrics (Cosine Similarity) determine compatibility score.
* **Swiping Interface**: Smooth, card-stack interface (left swipe = pass, right swipe = like, up swipe = superlike).
* **AI Icebreakers**: Contextual icebreaker prompts generated by LLMs based on shared profile traits.

### 4.3 Real-Time Chat & Communications
* **Message Delivery**: Sub-100ms real-time chat powered by WebSockets (Socket.IO) backed by a Redis adapter.
* **Media Exchange**: Encrypted photo/video sharing through signed S3/R2 URLs.
* **Real-time Image Censoring**: In-transit NSFW image censoring using the AI media service before displaying to the recipient.
* **WebRTC Video Calls**: Peer-to-peer secure video calls with Twilio Network Traversal (STUN/TURN) servers.

### 4.4 Geolocation & Maps
* **Location-Based Querying**: PostgreSQL PostGIS extension for rapid spatial queries within a user-defined radius.
* **Dynamic Geofencing**: Automatic location updating via background GPS in mobile or browser geolocation API (with user permission).
* **Google Maps Integration**: Visualizing public meetup points or localized events.

### 4.5 Dashboards
* **Admin Dashboard**: System health, financial reporting, user growth metrics, system configurations.
* **Moderator Dashboard**: Queue of flagged profiles, NSFW image reports, chat logs escalation (encrypted/redacted), account suspension tools.
* **Support Dashboard**: Customer tickets, billing inquiries, account recovery, refund processing.

## 5. Non-Functional Requirements

### 5.1 Scalability & Availability
* **High Availability**: The API and database must target 99.99% uptime.
* **Scalability**: Horizontal pod autoscaling (HPA) in Kubernetes based on CPU/memory usage.
* **Db Scalability**: Read-heavy operations (e.g., query match queue) must query read replicas.

### 5.2 Latency & Performance
* **API Response Time**: 95th percentile (P95) response time under 150ms for standard endpoints.
* **Image Delivery**: Cloudflare CDN edge caching for compressed WebP assets.
* **Memory Caching**: Cache user sessions, match statuses, and configuration parameters in Redis.

### 5.3 Security & Compliance
* **Data Encryption**: AES-256 for data at rest, TLS 1.3 for data in transit.
* **Privacy Controls**: Strict adherence to GDPR (Right to be Forgotten, Data Portability) and CCPA.
* **OWASP Compliance**: Protections against SQL injection, XSS, CSRF, and broken object-level authorization (BOLA).
* **PII Redaction**: Redact personally identifiable information (phone numbers, emails) in administrative logging.

### 5.4 Localization
* **Languages**: Full i18n support starting with English, Spanish, and French.
* **Currency**: Dynamic currency rendering based on location (USD, EUR, NGN, ZAR).
